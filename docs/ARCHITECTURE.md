# 自媒体中台架构与数据库设计

## 1. 产品边界

系统围绕一个闭环建设：**IP 定位 → 选题 → 内容生产 → 素材/剪辑 → 多平台发布 → 数据采集 → 获客/服务 → AI 复盘与下一步行动**。

首版采用单组织、多成员模型。每位创建者拥有一个或多个 IP，成员通过管理员分配权限协作。平台数据采用双通道：

- 官方开放 API：OAuth/API Token 授权后定时同步，仅保存服务端加密令牌，不保存平台密码。
- 文件导入：没有开放 API、审核未通过或接口不稳定的平台，使用平台后台导出的 CSV 每日上传；后续增加 XLSX 模板映射。

## 2. 系统架构

```text
浏览器
  ├─ 经营总览 / IP 定位 / 选题 / 内容 / 素材
  ├─ 账号矩阵 / 数据上传 / 获客 / 客户服务
  └─ AI 洞察 / 系统设置 / 用户权限
         │ HTTPS
         ▼
Nginx ── Next.js Web + API
             ├─ Auth/RBAC
             ├─ 业务服务层
             ├─ 数据导入与标准化
             ├─ 平台连接器适配层
             └─ 大模型路由与推断
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
 PostgreSQL     对象存储      商用模型 API
 结构化数据     视频/图片      OpenAI/Claude/
               音频/文档      Gemini/DeepSeek
```

生产环境由 Docker Compose 编排，PostgreSQL 只在内部网络开放；应用经 Nginx 暴露。素材文件不应存数据库，推荐接入阿里云 OSS，数据库仅保存对象 Key 和元数据。异步同步、转写、剪辑及 AI 分析后续增加 Redis + Worker，避免长任务阻塞网页请求。

## 3. 功能模块

| 模块 | 核心能力 | 主要输入 | 主要输出 |
|---|---|---|---|
| 经营总览 | KPI、趋势、待办、异常提醒 | 全域标准化数据 | 今日行动清单 |
| IP 定位 | 人设、受众、价值主张、内容支柱 | 访谈/问卷/历史内容 | IP 定位档案 |
| 选题策划 | 选题池、评分、排期、AI 扩写 | 热点、受众痛点、历史表现 | 内容日历 |
| 内容生产 | 脚本、文案、版本、审批、发布 | 选题与素材 | 跨平台作品 |
| 素材剪辑 | 素材库、标签、转写、剪辑任务 | 视频/音频/图片/文档 | 成片及衍生素材 |
| 账号矩阵 | 账号档案、授权、同步、每日上传 | API/CSV/XLSX | 标准账号与作品指标 |
| 获客中心 | 线索归因、评分、阶段、跟进 | 私信/表单/企微/手工录入 | 销售机会 |
| 客户服务 | 服务单、交付节点、满意度、复购 | 已成交客户 | 服务结果与案例 |
| 数据洞察 | 归因、对比、异常、预测、AI 建议 | 指标、内容、线索、收入 | 洞察与可执行任务 |

## 4. 核心数据模型

### 身份与权限

- `users`：后台用户、角色、启停状态。
- `sessions`：哈希后的登录会话、过期时间、终端信息。
- `auth_events`：登录审计与限流依据。

### IP 与内容生产

- `ips`：IP 名称、定位、受众、价值主张、人设、内容支柱。
- `topics`：选题、切入角度、受众痛点、评分、状态与排期。
- `contents`：作品主档、平台作品 ID、所属账号、正文、状态和发布时间。
- `assets`：素材元数据、对象存储 Key、标签、转写文本和处理状态。

### 平台账号与指标

- `accounts`：平台、账号标识、主页、同步方式、连接状态和最新粉丝数。
- `platform_connections`：授权方式、加密凭据、权限范围、过期时间及错误状态。
- `account_daily_metrics`：按“账号 + 日期”唯一，保存粉丝、曝光、播放、互动、主页访问、线索和收入。
- `metrics`：作品级快照，保存播放、曝光、赞评转藏、线索和收入。
- `import_batches`：文件导入批次、成功/失败数量和逐行错误。

### 获客、服务与决策

- `leads`：线索来源账号/内容、联系方式、意向、评分、阶段和下次跟进时间。
- `service_cases`：客户服务单、优先级、负责人、期限和交付结果。
- `ai_insights`：分析周期、证据、置信度、模型信息和建议。
- `action_tasks`：由人工或 AI 洞察生成的可执行任务。
- `model_configs`：不同用户的大模型选择；API Key 继续使用服务器密钥，不写入数据库。

## 5. 数据采集规范

标准账号日指标字段：

```text
date, followers, follower_delta, impressions, views,
engagements, profile_visits, leads, revenue
```

导入必须满足：账号归属校验、5MB 文件限制、日期格式校验、非负数清洗、同账号同日期幂等更新、批次审计。平台连接器负责把各平台字段映射为同一标准，原始文件后续可选存入 OSS 便于追溯。

## 6. AI 推断流程

1. 每日采集账号和作品指标并完成质量检查。
2. 计算增长率、互动率、线索率、内容价值分和收入归因。
3. 与 7/30/90 日基线及同账号历史内容比较，检测异常和机会。
4. 先用规则与统计生成结构化证据，再交给可切换大模型解释，避免模型凭空编造数字。
5. 将建议写入 `ai_insights`；用户确认后转为 `action_tasks`，执行结果回流下一轮分析。

模型路由建议：短文案/标签使用低成本快速模型；定位、复盘和策略使用强推理模型；敏感客户数据默认脱敏后调用商用 API。

## 7. 平台接入策略

优先使用平台官方开放平台，不采用模拟登录、抓取密码或绕过风控的方案。每个平台连接器实现统一接口：授权、刷新令牌、同步账号、同步作品、同步指标、健康检查。不可接入的平台永久保留文件导入通道，不影响统一分析。

接入账号时只需要提供：平台名称、账号主页、官方开放平台应用信息或 OAuth 授权。不要在聊天中发送账号密码、浏览器 Cookie、短信验证码。

## 8. 迭代顺序

1. 账号矩阵、每日 CSV 导入、真实经营总览。
2. IP 定位、选题池、内容日历、作品管理。
3. 线索中心、客户服务、内容到收入归因。
4. OSS 素材库、转写、剪辑任务和成片版本。
5. 首批官方平台连接器与定时任务。
6. AI 洞察、预测、实验对照和自动行动建议。

每一期都以“可录入、可查询、可追溯、可导出”为完成标准，避免只有展示页面而没有真实数据闭环。
